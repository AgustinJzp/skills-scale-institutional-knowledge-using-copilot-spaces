# OctoAcme — Cross-Functional Collaboration Checklist

## Purpose
Ensure smooth handoffs and clear communication across roles throughout the project lifecycle. This checklist addresses common gaps in cross-functional projects and reinforces role interactions.

## When to Use
- During project planning phase
- At sprint kickoff
- Before major releases or handoffs
- After retrospectives to improve collaboration

## Pre-Project Kickoff (Product Manager + Project Manager + Tech Lead)

### Planning & Alignment
- [ ] Product Manager has defined success metrics and acceptance criteria
- [ ] Project Manager has identified all required roles (Dev, QA, Design, Tech Writer, BA, etc.)
- [ ] Business Analyst has clarified business requirements and constraints
- [ ] Timeline and dependencies are documented and shared
- [ ] Role RACI (Responsible, Accountable, Consulted, Informed) matrix is defined
- [ ] Stakeholder communication plan is established

### Risk & Feasibility Review
- [ ] Developers have reviewed scope for technical feasibility
- [ ] UX Designer has outlined user research or design approach
- [ ] QA Lead has drafted quality strategy and test plan
- [ ] Known blockers and dependencies are documented
- [ ] Mitigation plans are in place for high-risk items

---

## Sprint Planning (All Roles)

### Requirements Clarity
- [ ] Product Manager presents user stories with clear acceptance criteria
- [ ] Business Analyst confirms requirements align with business goals
- [ ] Developers ask clarifying questions and confirm estimates
- [ ] QA Lead outlines test approach for the sprint
- [ ] UX Designer provides mockups or design guidance if applicable

### Capacity & Commitment
- [ ] All roles have confirmed availability and capacity
- [ ] Task dependencies and handoff points are identified
- [ ] Communication protocol for blockers is established
- [ ] Definition of Done is agreed upon across all roles

---

## During Sprint Execution

### Daily Standups (All Roles)
- [ ] Each role reports progress, blockers, and dependencies
- [ ] Blockers are escalated immediately; not deferred
- [ ] Cross-team dependencies are visible and tracked
- [ ] QA Lead flags quality concerns early

### Mid-Sprint Check-Ins (as needed)
- [ ] Developers sync with QA Lead on test strategy and coverage
- [ ] UX Designer reviews implementation for design fidelity
- [ ] Technical Writer updates documentation draft based on changes
- [ ] Business Analyst validates scope adherence
- [ ] Project Manager flags any risk or schedule changes

### Code & Design Reviews
- [ ] Pull requests include issue link and clear description
- [ ] Developers request review from QA Lead (for testability feedback)
- [ ] Design team reviews implementation for UX fidelity
- [ ] Technical Writer reviews for documentation updates needed

---

## Pre-Release Handoff

### Quality Gate
- [ ] QA Lead confirms all acceptance criteria are met
- [ ] Automated tests pass and code coverage is acceptable
- [ ] Manual QA and usability testing are complete
- [ ] Known issues are documented with severity and workarounds
- [ ] Accessibility standards have been validated

### Documentation & Communication
- [ ] Technical Writer has completed user and developer docs
- [ ] Release notes are drafted with all stakeholder input
- [ ] Deployment runbook is reviewed and ready
- [ ] Rollback and mitigation plan is documented
- [ ] Support team has been briefed on key changes

### Stakeholder Readiness
- [ ] Product Manager has prepared announcement or comms
- [ ] Stakeholders and leadership have been notified of timeline
- [ ] Customer support or success team has been trained
- [ ] Analytics or monitoring dashboards are configured

---

## Post-Release (All Roles)

### Verification & Monitoring
- [ ] Smoke tests pass in production
- [ ] Monitoring and error alerts are active
- [ ] Performance is within acceptable thresholds
- [ ] Support team is on standby for issues
- [ ] Key metrics are being tracked

### Rapid Response Protocol
- [ ] Critical bugs are triaged within 1 hour
- [ ] Rollback decision is made within agreed timeframe
- [ ] Post-incident blameless retrospective is scheduled

---

## Retrospective & Learning (All Roles)

### Retro Participants
- [ ] All core roles participated (Dev, QA, PM, Design, Tech Writer, BA)
- [ ] Stakeholders or dependent teams invited as needed
- [ ] Timebox: 45–75 minutes
- [ ] Anonymous feedback captured if needed

### Outcomes
- [ ] What went well (celebrate wins)
- [ ] What could be improved (at least 2–3 items)
- [ ] Action items assigned with owners and due dates
- [ ] Follow-up on previous action items documented
- [ ] Process improvements are logged for future projects

### Action Item Tracking
- [ ] Action items are added to backlog with clear owners
- [ ] Success criteria for each action are defined
- [ ] Due dates are realistic and communicated
- [ ] Review scheduled for next sprint or cycle

---

## Collaboration Red Flags

If you observe any of the following, escalate and address immediately:

- ❌ Requirements are unclear or change mid-sprint without impact assessment
- ❌ QA Lead is not included in planning or design reviews
- ❌ No communication across roles for 2+ days
- ❌ Technical Writer is brought in at the last minute with no lead time
- ❌ UX Designer's feedback is ignored without documented reason
- ❌ Business Analyst's feasibility concerns are not addressed
- ❌ Blockers are not surfaced until daily standup
- ❌ Acceptance criteria or Definition of Done are not met at PR review
- ❌ No shared understanding of "release readiness"
- ❌ Retrospective action items are not tracked or reviewed

---

## Tips for Effective Cross-Functional Collaboration

1. **Clarity over assumptions** — Always ask clarifying questions. Document decisions.
2. **Early involvement** — Bring QA, Design, and Tech Writer into planning, not just execution.
3. **Visible dependencies** — Use project board to mark cross-team handoffs.
4. **Respect timelines** — Give Tech Writer, Design, and QA adequate lead time.
5. **Celebrate wins** — Acknowledge each role's contribution in retrospectives and standups.
6. **Blameless escalation** — Focus on fixing problems, not blaming individuals.
7. **Single source of truth** — Keep docs, requirements, and status in one place.
8. **Regular sync rituals** — Standups, sprint planning, and retros keep alignment strong.
